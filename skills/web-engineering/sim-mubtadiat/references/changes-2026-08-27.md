# SIM Mubtadiat — changes & gotchas 2026-08-27

## SERVICE-WORKER PRECACHE TRAP — #1 reason "gak berubah" after a verified deploy
`frontend/public/sw.js` has a `urlsToCache` precache array. `rapot.html` + `/dist/rapot.html`
were IN that list → the SW served its own cached copy of rapot.html forever, even though:
(a) the container copy md5 matched the new file, (b) Cloudflare returned
`cf-cache-status: DYNAMIC` + `cache-control: no-cache`, (c) the served HTML over curl already
had the new bytes. Owner kept seeing the OLD layout. Bumping only `CACHE_NAME` (v30→v31) did
NOT fix it because the page itself was precached and the old SW kept control.

FIX: (1) REMOVE html pages from `urlsToCache` (keep only truly static: logo, favicon,
style.css) so pages are always network-first, AND (2) bump `CACHE_NAME`. Then the owner must
Unregister the SW (DevTools→Application→Service Workers→Unregister + Clear site data) OR clear
site data on mobile — a plain reload keeps the old SW alive.

DIAGNOSTIC when "belum berubah" persists after rebuild:
`curl -s URL/rapot.html | grep <new-pattern>` confirms the server is correct. If the server has
it but the browser doesn't, it's the SW — not Cloudflare, not the build. Don't keep bumping CSS
values (wasted ~4 rebuild cycles doing 60→130→220px thinking the geser value was wrong when the
file wasn't even loading in the browser).

## Raport identity right-column alignment
`padding-left` on `.st-right` shifts the raport identity right-column (No.Tamrin/Bagian) to
align with the الكتب الدراسية column. Owner iterates by eye ("kurang banyak"/"belum lurus") —
Chromium auto-render for pixel measurement OOMs on this 2GB VPS (exit -9, ~265MB free), so you
CANNOT measure alignment server-side; rely on owner visual feedback and ask for coarse magnitude
("kurang dikit / banyak / kejauhan") to converge in fewer rebuild cycles.

## Absensi pengajar is KUARTAL now, not monthly S/I/T (migration 049)
Table `absensi_pengajar_kuartal` (pengajar_id, tahun_ajaran, kuartal_1, kuartal_23, kuartal_4 —
3 numeric cols; K2&3 merged). Old `absensi_manual_pengajar_bulanan` DROPPED. Input + Rekap tabs
live in absensi-manual.html / rekap.html (tab pengajar) + rekap.js. Endpoint
`/api/absensi-pengajar-kuartal` (GET filter tingkatan_id/kelas_id/tahun_ajaran, LEFT JOIN so
teachers w/o record still show; POST batch upsert). Santri absensi stays monthly S/I/T.
Empty cells (id==0 / no record) render blank, not pre-filled 0 (both santri & pengajar grids).

## Raport display rules
- ALL mapel of the year show in BOTH semesters — `laporan.go` raport query has the
  `aktif_kuartal` filter disabled via `OR TRUE`; mapel only taught 1 kuartal/semester render `-`
  (empty khos/am) in the other semester via `fmtNilai(x)||'-'` in rapot.js.
- Al-Bayan `الرديء` (rodli', ≤5) prints as `المثبت` (Musbat) in the PRINT raport ONLY (rapot.js
  transform, still red) — Penilaian menu + DB keep `الرديء`.
- Kelas field = `kelas_nama + ' ' + tingkatan_nama` (e.g. "3 Aliyah"); backend returns
  `tingkatan_nama` in the raport payload.

## Mapel `nama_indo` column (migration 050)
Riwayat Akademik + Penilaian + wali view display `nama_indo` (admin-typed Indonesian), fallback
to Arab nama_kitab when empty (NOT the kitab-translate.js dictionary anymore for riwayat).
RAPORT CETAK still uses Arab nama_kitab. Riwayat mapel order = raport order (`ORDER BY m.urutan`).
Kelola Mapel form (kelas.html/kelas.js) has the "Nama Indonesia" input.

## Import santri is PARTIAL now
`ImportSantriBatch` commits per-row (valid rows land, bad rows skipped + collected in
`res.Errors` {baris,nama,pesan}); handler returns sukses/gagal/errors; santri.js shows colored
badges + red table Baris|Nama|Alasan + 📋 Salin button. ALSO fixed a latent bug: the INSERT had
19 cols but `$1..$18` + `'aktif'` literal placeholder mismatch → import ALWAYS failed before;
now `$1..$17` + `'aktif'`.

## Manual add santri assigns to class immediately
santri.js POST /api/santri includes `bagian_awal_id` in payload (backend CreateSantri sets
bagian_id + inserts riwayat_bagian in one tx). The old second call to
`/api/perpindahan/naik-kelas` was removed — it was leaving santri stuck in "belum di kelas".

## Detail-santri riwayat absensi month range
Grid must use the SAME month range (mulai→selesai from kalender_semester_hijri) as Input Manual
& Rekap, NOT 12 months × each Hijri year. Iterating tahun_hijri and rendering 12 months/year
produced a 24-month grid instead of the ~11-month TA range. Build from mulai_bulan/mulai_tahun →
selesai_bulan/selesai_tahun inclusive. Empty months still show (value 0).
